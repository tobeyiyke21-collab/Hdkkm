The recipe, in one line

URL says which product → grab its data → pour it into the template → send the finished page to the visitor.

One template, any number of products, a different URL for each. That's all "dynamic pages" means.

Anatomy of a URL (and what's a "slug"?)

A URL is a web address. For our shop, the last piece is special: it changes for each product. That piece is called a slug.

🎮 Type or edit a URL. See it split into parts

So what is a slug?

A slug is the human-friendly name of a page, written in lowercase letters, numbers and hyphens. No spaces, no weird symbols. Type a product name below and see how it turns into a slug.

The model: where products live

A model is a Python class that describes one kind of thing you store. Django turns it into a database table. One class = one table. Each product = one row.

from django.db import models
from django.urls import reverse


class Product(models.Model):
    name = models.CharField(max_length=200)
    slug = models.SlugField(unique=True)
    price = models.DecimalField(max_digits=8, decimal_places=2)
    description = models.TextField(blank=True)
    in_stock = models.BooleanField(default=True)

    def __str__(self):
        return self.name

    def get_absolute_url(self):
        return reverse("product_detail", args=[self.slug])

Line by line

CharFieldShort text (a name). max_length is required.
SlugField(unique=True)The URL piece. unique = no two products may share a slug, or their URLs would clash.
DecimalFieldMoney. Use this, not floats, to avoid rounding bugs.
TextFieldLong text. blank=True = may be left empty.
BooleanFieldYes/no. Here: in stock?
__str__How a product is displayed in the admin and the shell.
get_absolute_urlA handy "what's my URL?" method. We'll use it in lesson 11.

Create the table

Models are just Python until you tell Django to build the table. Two commands:

urls.py: teach Django your addresses

Now the magic ingredient. We tell Django: "when the address looks like /products/SOMETHING/, run the product_detail view and hand it SOMETHING."

Step 1: the app's own urls.py

Create a new file products/urls.py:

from django.urls import path
from . import views

urlpatterns = [
    path("", views.product_list, name="product_list"),
    path("<slug:slug>/", views.product_detail, name="product_detail"),
]

Step 2: plug it into the project's urls.py

from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path("admin/", admin.site.urls),
    path("products/", include("products.urls")),
]

include() means: "anything starting with products/, let products/urls.py handle the rest."

The star: <slug:slug>

Angle brackets are a capture. Read it as <converter:variable_name>:

  • converter (slug): what shape is allowed (letters, numbers, hyphens)
  • variable_name (slug): the name the view receives it under
🎮 URL matcher: test addresses against your patterns
Order matters. Django checks patterns top to bottom and uses the first match. Put specific patterns before general ones.

views.py: the brain

A view is just a Python function. It receives the visitor's request (and the captured slug), fetches data, and returns a page.

from django.shortcuts import render, get_object_or_404
from .models import Product


def product_list(request):
    products = Product.objects.all()
    return render(request, "products/product_list.html", {"products": products})


def product_detail(request, slug):
    product = get_object_or_404(Product, slug=slug)
    return render(request, "products/product_detail.html", {"product": product})

Walk through product_detail

  1. def product_detail(request, slug): Django passes request (info about the visitor) and slug (captured from the URL, same name!).
  2. get_object_or_404(Product, slug=slug): "find the product whose slug equals this. If none exists, show a 404 page."
  3. render(request, "…html", {"product": product}): pours the product into the template. The dictionary is the context: names the template can use.
🎮 Run the view: what happens for each slug?
Why not just .get()? If the slug doesn't exist, .get() crashes (server error 500). Visitors typo URLs constantly. get_object_or_404 gives them a polite "page not found" instead.

Templates: fill-in-the-blank HTML

A template is normal HTML plus a few special Django tags. Two kinds matter today:

{{ … }}

Print a value. {{ product.name }} shows the product's name.

{% … %}

Do logic. {% if %}, {% for %}, {% url %}…

Where to save it

Django looks for templates inside templates/ in your app. Repeat the app name once more inside (a Django habit that avoids name clashes):

products/
└── templates/
    └── products/
        ├── product_detail.html   ← this lesson
        └── product_list.html     ← lesson 11
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>{{ product.name }} | My Shop</title>
</head>
<body>
  <h1>{{ product.name }}</h1>
  <p>${{ product.price }}</p>
  <p>{{ product.description }}</p>

  {% if product.in_stock %}
    <button>Add to cart</button>
  {% else %}
    <p>Sorry, sold out.</p>
  {% endif %}

  <a href="{% url 'product_list' %}">← All products</a>
</body>
</html>

Bonus: the product list page

Visitors need a page that shows all products and links to each one. Same idea, with a loop.

<h1>All products</h1>

<ul>
  {% for product in products %}
    <li>
      <a href="{{ product.get_absolute_url }}">{{ product.name }}</a>
      ${{ product.price }}
    </li>
  {% empty %}
    <li>No products yet.</li>
  {% endfor %}
</ul>

The new things

  • {% for product in products %} repeats the block once per product. products came from the view's context.
  • {% empty %} shows if the list has nothing in it.
  • {{ product.get_absolute_url }} calls the method we wrote in the model. It builds /products/red-running-shoes/ for us.
  • Alternative: {% url 'product_detail' product.slug %} does the same thing by looking up the URL's name.
🎮 Flip products on and off in the "database"
Tick ⌚ Smart Watch: instantly it has a page, a link and a URL. No code changes.
Why use {% url %} or get_absolute_url instead of typing links by hand? If you ever change the URL pattern (say /shop/ instead of /products/), every link updates itself.

Gotchas and how to fix common errors

Everyone hits these. Now you'll recognise them. 🧯

1. Slug or ID in the URL?

ID

/products/7/

Simple, but meaningless to humans and search engines.

Slug ✅

/products/red-running-shoes/

Readable, shareable, better for SEO. Keep it unique.

2. Security: Django escapes things for you

If a product name contains HTML like <b> or a sneaky <script>, Django shows it as plain text by default. That protects you from XSS attacks. Try it:

🎮 Escaping demo

{{ name }} (safe, default)

{{ name|safe }} (dangerous)

We stripped the nasty bit here. A real page wouldn't.
Rule: never use |safe on text that users can type.

3. Error decoder

TemplateDoesNotExist

Meaning: Django can't find your .html file.

Fix: check the path products/templates/products/product_detail.html exactly, and that "products" is in INSTALLED_APPS.

Page not found (404) on a URL that should work

Meaning: no pattern matched, or the slug isn't in the database.

Fix: check include("products.urls"), the trailing /, and that the product's slug is spelled exactly the same.

NoReverseMatch

Meaning: {% url 'name' %} couldn't build a link. The name is wrong, or an argument is missing.

Fix: make sure name="product_detail" exists in urls.py and pass the slug: {% url 'product_detail' product.slug %}.

Product matching query does not exist

Meaning: you used .get() and nothing matched.

Fix: use get_object_or_404.

IntegrityError: UNIQUE constraint failed: products_product.slug

Meaning: you tried to save a second product with an existing slug.

Fix: give it a different slug (e.g. red-hat-2).

no such table: products_product

Meaning: you forgot to create the table.

Fix: run python manage.py makemigrations then python manage.py migrate.

4. The trailing slash

Our patterns end with /. If someone types /products/coffee-mug (no slash), Django automatically redirects to the slash version. That's the APPEND_SLASH setting, on by default.
